# 天工用户手册

> 适用版本：`@jos/workbench 0.8.0`（2026-11-04 能力快照）
> 英文能力清单见 [../README.md](../README.md)。

天工（Tiangong）是 DSH 里的**需求到交付**工作台：你提需求，它负责规划、派活、验收、交付。
它不替你写代码，而是把一个需求拆成一组有依赖关系的任务卡，派给子 agent 执行，再用测试证据判断
“真的完成了吗”。

---

## 1. 它在后台做了什么

```
你提交需求
  → 插件开一个 job（项目里的一次交付）
  → 给项目绑定一个「投递会话」，唤醒主 agent 规划
  → 主 agent 用 workbench_submit_plan 提交任务图（DAG）
  → 插件按依赖把「就绪卡」派给子 agent，子 agent 带测试证据回报
  → 叶子卡全绿 → job 完成 → 写交付记录
```

- 规划有预算：约 10 次工具调用 / 3 分钟；2 分钟会发一次提醒，5 分钟没交计划就转人工（可在配置里调）。
- 卡片**只有拿到真实测试证据才算完成**：退出码 0、通过数 >0、失败数 0；否则转人工判断。
- 每一步都有账本记录，事后可查。

## 2. 安装与启用

1. 本机已装好 DSH（`dsh` ≥ 0.2.1-rc.0）。
2. 在插件管理里安装本包（或 profile 里 `link:` 本目录），并确保 bundles 里有 `@jos/workbench`。
3. **完全退出 DSH（⌘Q）再启动**，侧栏出现「天工」入口。
4. 想用对话栏的语音输入，还要启用 DSH 的语音输入 bundle（`voice-input-bundle`）；
   天工与主聊天**共用同一套语音模型和设置**，准备一次即可。

## 3. 界面导览

| 位置 | 用来做什么 |
|---|---|
| **看板** | 每个项目一张卡；创建项目、删除项目卡、看哪些任务在跑 |
| **项目页** | 交付物、应用预览、进入任务列表 |
| **任务列表** | 按**任务组**展示：一个根任务一张卡，修改记录挂在卡内 |
| **工作项卡片** | 驾驶舱画布或「任务」里点任意卡片 → 弹出详情：状态/阶段/负责人/依赖/子会话/指令/验收/调用技能/产物/卡点（拖动卡片不会弹窗） |
| **坐舱（任务驾驶舱）** | 一个任务的完整视图：团队分工、阶段、面板、对话、工作区、控制按钮 |

任务驾驶舱布局：

- 中间：团队分工画布（主代理 + backend / frontend / qa 泳道）
- 左侧仪器栏：进度、阶段、任务（可折叠）
- 右侧仪器栏：等你决定、决策流、交付物
- 右侧（或窄屏下方）：任务对话栏

## 4. 第一次交付

1. **建项目**：看板点「＋ 创建」，三步向导：
   - **基本信息**：项目名（如「公司管理」）；
   - **项目类型**：软件交付 / 文案内容 / 自定义（决定主 agent 的人格、工具面与工作区模板）；
   - **工作区**：可以直接输入绝对路径，也可以点「选择文件夹…」从本机硬盘选择；
     留空自动分配（`~/.dsh/workbench/apps/<项目>`）。选软件/文案类型时会生成
     `AGENTS.md` 和 `docs/README.md`（不覆盖已有文件）。
2. **提需求**：项目页点「＋ 新建任务」，输入需求，或上传 `.md` / `.markdown` / `.txt`（≤512 KiB）。
3. **看规划**：卡片先显示「自动·规划中」；主 agent 交计划后出现任务卡（0/N 完成）。
4. **看执行**：卡片进入「自动·执行中」，任务树逐张变绿。
5. **看结果**：全部叶子卡完成后，卡片变「已完成」，项目页出现交付物；驾驶舱可查看结果。

> 规划阶段如果超过 2 分钟还没出计划，会收到一条提醒；超过 5 分钟没交计划会停在「等你决定」，
> 你可以批准/驳回，或调大 `planTimeoutMs`（见第 10 节）。

## 4.5 项目类型与能力包

| 类型 | 主 agent 人格 | 工具面 | 工作区模板 |
|---|---|---|---|
| 软件交付 | 交付 lead：规划/派卡/验收 | 规划 + 读文件 + 派卡 + 验证；屏蔽 3D/浏览器/机器人工具 | `AGENTS.md` + `docs/` + 验收脚本 |
| 文案内容 | 内容 lead：结构/撰写/审校 | 读/写/搜索/审校；屏蔽 shell、3D、浏览器、机器人工具 | `AGENTS.md` + `docs/` + 审校清单 |
| 自定义 | 部署默认 agent | 继承部署默认，不额外屏蔽 | 不生成 |

- 类型存在账本里（`projectKind` + `profile`），不是只存在浏览器；
- 类型对应的两套 preset（`workbench-software` / `workbench-copy`）由插件包自动安装，
  可在 profile 里覆盖；
- 工具面屏蔽只作用于**投递会话本身**；子 agent 的工具面和技能目录目前不额外收窄（后续版本）；
- 已有会话保持创建时的组合；换类型请新建项目，或改 profile 里的 preset 后重启。

## 5. 看懂任务卡

- **状态**：`自动·规划中` → `自动·执行中` → `已完成` / `等你决定` / `已暂停` / `已终止`。
- **进度**：`3/9 完成 · 2 阻塞 · 1 待决定`；完成后显示结果摘要（工作项数、交付物数）。
- **任务组**：根任务卡里带「后续 N 次修改」的紧凑行，行上显示状态和进度；
  根卡上「● N 进行中」提示组内有修改在跑。
- **token**：卡片底部显示本任务消耗；注意这是项目投递会话的累计量，同一项目里后面的任务会包含
  前面历史的消耗（上限值，不是单任务净增量）。

## 6. 修改/修复（change request）

已完成任务不直接改，改动会作为**新任务**创建并关联到原任务：

1. 打开已完成任务的驾驶舱，主按钮是「＋ 修改/修复」。
2. 弹窗预填 `修改「任务名」：`，选择类型：**修改 / 修复 bug / 新增功能**，补全描述。
3. 提交后自动进入**新任务**的驾驶舱：它有自己的计划、卡片、测试证据和交付物。
4. 原任务保持不变；任务列表里它能从根卡的「后续修改」行进入，驾驶舱顶部有
   `任务组：根任务 › 本次修改` 的面包屑，可点祖先切回。

> 修改任务和新建任务走同一条闭环入口（`/workbench/requirements`），由调度器自动规划派发，
> 不需要手动点「开始执行」。

## 7. 驾驶舱操作

| 按钮 | 作用 |
|---|---|
| ▤ 面板 / 收起面板 | 隐藏/显示左右仪器栏 |
| ▶ 开始执行 | **仅旧任务**（没有 requirement 的历史计划）显示：手动让 agent 执行一轮 |
| 💬 收起对话 | 打开/收起任务对话栏 |
| 📁 工作区 | 给任务绑定 DSH 工作区（任务在这里干活） |
| 暂停 / 继续 | 暂停派发，并**中断每张在飞卡上的子 agent 当前轮**（会话保留）；「继续」让这些子 agent 接着做原来的卡，而不是重做 |
| 终止 | 只停止派发新卡（需要确认）：**不结束正在运行的 agent**，之后可点「继续」恢复 |
| ＋ 修改/修复 | 已完成任务创建后续修改（见第 6 节） |
| 等你决定 | 审批/驳回卡点（不可逆动作、测试没绿、预算/轮数超限等） |

**工作区**：任务在哪个目录干活由工作区决定；一个项目通常对应一个交付目录。
**交付物**：右栏列出产物路径，项目页可查看/预览。

---

## 8. 对话栏

- 只显示**你的需求**和**每一轮的最终结论**；规划指令、工具调用、子 agent 通知等过程信息不显示。
- 你可以随时在这里给 agent 发消息（比如"把蛇改细一点"）、粘贴图片（⌘V / 拖入 / 🖼，最多 4 张、单张 ≤8 MB）。
- 「在 DSH 打开」可跳转原生会话；「绑定已有对话」可换会话；「解绑」断开当前任务与对话。
- 对话栏每 3 秒刷新一次，自动跟到最新消息。

## 9. 语音输入 🎤

- 点 🎤 开始录音（按钮变红、图标变 ⏹），再点一次停止；转写结果**插入输入框**，不会自动发送。
- 识别在宿主完成：浏览器录音 → 重采样成 16 kHz 单声道 WAV → `POST /workbench/transcribe`
  → 宿主语音服务（默认 SenseVoice 本地）转写。
- **与 DSH 主聊天共用同一个模型、同一套设置和同一份模型文件**
  （`~/.dsh/speech-to-text/sensevoice`）；主聊天里准备过一次，这里直接可用。
- 第一次录音会弹系统麦克风授权；宿主没有启用语音 bundle 时按钮会提示
  「当前宿主没有启用语音识别」，不会假装成功。
- 识别模型未准备时返回准备相关错误，需要先在 DSH 的语音输入设置里完成模型准备。

## 10. 配置与调参

在 profile 的 `cordis.patch.yml` 里给 `workbench` 行加 `config`（重启生效）：

```yaml
- id: workbench
  config:
    autoRun: true
    planTimeoutMs: 300000     # 规划硬超时（5 分钟）
    planNudgeMs: 120000       # 2 分钟提醒
    budgetTokens: 400000      # 单任务 token 上限；0 表示不限制
    maxRounds: 60             # 唤醒轮数上限
    stallAfterWakes: 6        # 连续唤醒无进展 → 人工
```

常用场景：

- **复杂需求规划总超时**：把 `planTimeoutMs` 调到 600000–900000，或在需求里要求先开 `diagnose` 卡。
- **想控制成本**：设 `budgetTokens`（或 `budgetUsd` + 价格），超限转人工。
- **不想自动跑**：`autoRun: false`，任务只规划不派发（旧手动模式）。

其他可选项：`dataDir`、`appsRoot`、`agentPreset`、`provider`/`model`（旧规划器）、`wakeCooldownMs`、
`loopTickMs`、`priceInputPerMTok`/`priceOutputPerMTok`。完整表见 [../README.md](../README.md#configuration)。

## 11. 数据与审计

- 账本：`~/.dsh/workbench/events.jsonl`（append-only，唯一真相）
- 需求文档：`~/.dsh/workbench/requirements/<jobId>.md`
- 旧规划器产物：`~/.dsh/workbench/deliveries/<runId>/{roles,design,review}.json`
- 交付物：项目工作区里（卡片显示相对路径）
- 视图状态（面板开合等）：浏览器 localStorage

删除项目卡只会写一条 tombstone 账本记录，**不会删除磁盘上的项目文件**。

## 12. 常见问题

**Q：卡片一直「规划中 / 0/0」，是不是卡死了？**
A：规划阶段没有卡片，所以进度是 0/0，只能看 token 增长。正常应在 2–3 分钟内出计划；
超过 2 分钟会收到提醒，5 分钟没交计划会转「等你决定」。

**Q：暂停后子 agent 会停吗？继续后会不会重做？**
A：新版（0.4.4）会：暂停时插件直接通过宿主 `sessionController.cancel` 停掉每张在飞卡绑定的
子会话当前轮（保留会话/收件箱/记录），继续时用 `sessionController.prompt` 给同一个子会话发
"接着做、不要重来"——不会从卡片提示重新执行，重启后也能冷恢复。
绑定关系由主 agent 在 spawn 子 agent 后调用 `workbench_bind_child` 记录；旧任务没有绑定，
暂停仍然只是停派发。

**Q：在哪里给任务选技能？**
A：**新建任务弹窗**里有一行「技能」：默认勾选项目类型推荐技能，可搜索已安装技能增删（最多 6 个），
也可勾选市场里未安装的技能（标黄，规划时会先问你安装或降级）。任务卡和驾驶舱都能在**开跑前**修改同一个技能池，
开跑后只读；卡片详情里「要求技能 / 实际调用技能」两栏对照。

**Q：卡片详情里的「调用技能」是什么？**
A：记录该卡子 agent 实际加载过的技能。投递 lead 规划前必须先 `workbench_find_skill` + `skill`，
子 agent 开卡前也要加载匹配技能；插件监听宿主 `skill` 工具调用并按子会话映射回卡片记录，所以列表是实际调用，不是模型自报。

**Q：需求文档里要不要写技能列表？DSH 没装的技能怎么办？**
A：不用每次写。插件会按项目类型推荐技能（软件：`create-implementation-plan`/`review-and-refactor`；
文案：`documentation-writer`），agent 只能从**已安装**的技能目录里选。需求里如果明确点名了技能，
规划时会把它们作为 `required` 传给 `workbench_find_skill` 核对：
- 已安装 → 正常加载；
- 未安装且必需 → 规划会先 `ask_user` 让你安装对应插件/技能，或批准"通用方式降级"；
- 未安装但可选 → 计划/卡片里注明降级，**不会假装加载**。

**Q：规划超过 5 分钟，提示 plan-timeout 怎么办？**
A：超时后系统会**停下**（不再每 5 分钟重发一遍规划指令），等你处理或等计划晚到后继续。
可以在任务对话里发一句"只提交计划，不要继续探索"，或先在决策流里处理该卡点。

**Q：卡片停在 0/N，没有"执行中"？**
A：说明还没把卡派给子 agent。检查对话栏里 agent 是否在跑、是否卡在长命令上；
本版本在发卡时会写 `claimed`，重启后应立刻显示「执行中」。

**Q：修改任务在哪？**
A：在根任务卡的「后续修改」行，或驾驶舱顶部的「任务组」chip；点进去就是新任务的驾驶舱。

**Q：为什么对话栏只有我的需求和一两条结论？**
A：这是设计：过程（工具调用、子 agent 通知、注入指令）被过滤，只保留每轮最终结论。

**Q：语音按钮点了没反应/报错？**
A：先确认 DSH 语音输入 bundle 已启用、模型已准备、系统麦克风权限已授权；
宿主没有语音服务时接口返回 501，会提示「当前宿主没有启用语音识别」。

**Q：token 数是这个任务真实的消耗吗？**
A：是投递会话的累计值；同一项目里后面的任务包含前面历史的消耗，属于上限值。

**Q：为什么没有「开始执行」按钮了？**
A：闭环任务由调度器自动派发，不需要手动执行；该按钮只给旧任务（`/workbench/start` 创建的、
没有 requirement 的计划）保留。

**Q：需求文档支持 docx/pdf 吗？**
A：暂不支持，会明确报「暂不可读」；请上传 `.md` / `.markdown` / `.txt` 或直接粘贴文本。

**Q：能让天工用 computer use 自动点浏览器吗？**
A：天工自己的任务闭环不依赖 computer use；这类"操作桌面/浏览器"的临时请求属于对话行为，
需要 profile 启用 computer use 插件并授权辅助功能/屏幕录制。动作类实时操作（如游戏）
不适合截图往返，建议用状态读取或逻辑测试验证。

## 13. 安全边界

- 所有 HTTP 路由同源校验，并经过宿主连接策略；面板不会跨源写入。
- 不可逆动作（合并 PR、发布、删表等）永远走人工泳道，不会被自动执行。
- 外部内容（网页、需求文档）只作为数据，不当作指令。
- 语音音频只在宿主内转写，不上传到第三方。
